# The Rising Mangaka: generated art in the studio scene (0.9.0 → 0.11.0)

## Context
After the illustrated upgrade, every panel has generated art but the main screen — the 320x180 canvas studio — still
looks as before, because the hybrid ruling kept the scene code-drawn. The owner asked to integrate all three options:
generated room backgrounds, generated props, generated characters, while keeping every animation and game-driven
behaviour (walking, moods, panic, outfits, day/night, seasons, story props, equipment appearing when bought).

Images come from Higgsfield `z_image` (owner-approved credits: ~0.15 each, 8.2 left; ~3 parallel jobs max).

Probes run while planning (2026-09-30):
- **Room**: a full furnished apartment came out beautiful but the model ignored the requested positions (window
  centred, door inboard). So furniture is NOT baked into backgrounds; see decision 2.
- **Characters**: one sheet gave a consistent mangaka across 10 frames (idle, 4-step walk, sit, drawing, hands-on-head
  panic, asleep). Characters are feasible; the open question is how they read at 24x32.

## Decisions
1. **Reverse the "nothing generated in the canvas" ruling** (DESIGN.md Art + Rulings, CLAUDE.md scene paragraph).
   `render(ctx, s, t, frame, art: SceneArt = NO_ART)` gets images passed in; `src/ui/scene/sceneImages.ts` builds one
   `HTMLImageElement` per registry ref once. `render.ts` never imports `registry.ts`. An image that is missing or not
   loaded falls back to today's code-drawn path (never a blank frame); a load triggers one repaint. `fakeCanvas.ts`
   gains a logged `drawImage` (`images[]` with order index `at`) and `fakeImage(id,w,h)`; `log` stays fillRect-only so
   the fill budgets keep measuring what is still code-drawn; new `*_ART` baselines sit beside 673/1079.
2. **Backgrounds are empty shells; furniture is sprites at existing coordinates.** Each tier's background is only
   ceiling/beams, wall surface and floor (tatami / planks / concrete). Its single alignment point is the wall/floor
   seam at canvas y 114, fixed by the manifest `crop`. The window frame, door or noren doorway, kitchenette, bookshelf,
   bed, poster frame, desk, chairs, equipment and front-row props are cutout sprites drawn with `drawImage` at the
   exact footprints the code-drawn pieces use today, in the same draw order. No actor spot moves.
3. **Night**: keep the existing overlay plus one dim fill after the background; no night-variant images.
4. **Characters go through the existing sprite system.** A new `--sprite` mode turns a generated pose cell into a
   24x32 (or cat 12x8, lying 30x14) string-map frame using PAL keys, emitted to `src/ui/scene/generated/*.ts` and
   validated by `frameRules` plus new `faceRules` (FACES window, mark slot, avatar crop). If a head fails `faceRules`,
   the hand-drawn anchor head (rows 0-15) is grafted on. Outfits stay palette swaps; assistants reuse seated frames.
   Fallback if frames don't read at 24x32: keep hand-drawn frames, use the sheets as reference for a hand redraw.

## Release 0.9.0 — rooms (branch `upgrade/0.9.0-rooms`)
1. Ruling + plumbing: `SceneArt`, `sceneImages.ts`, `render` signature, fallback wrapper (`drawFixedRoom` in
   `roomArt.ts`), `fakeCanvas` drawImage, repaint on load, tests (image first at 0,0,320,180; not-loaded falls back;
   sky still paints over; night dim present).
2. Palette: add the tier colours already literal in `roomArt.ts` to `ART_PALETTE`; art.test cap raised (≈12 KB per
   room, total cap to 160 KB — recorded as a ruling).
3. Generate 3 shells (+rerolls), pixelate to 320x180 at 32 colours (try `area` and `nearest`, keep the crisper),
   `ROOM_ART` registry record, mount. Acceptance: seam within ±2 px of y 114, no furniture drawn in.
4. Structural props that define the room, as sprites at today's footprints: window frame, door/noren doorway,
   kitchenette, bookshelf, bed, poster frame (generated as 2 sheets). Code-drawn on top as today: sky, season layer,
   bars, sill, volumes, clock, corkboard, calendar, posters, lights, ambient light.
5. Docs (DESIGN.md scene + Art + Rulings, CLAUDE.md), `npm run check`, preview check at desktop and 375x667, all three
   tiers, day and night, four seasons.

## Release 0.10.0 — props (branch `upgrade/0.10.0-props`)
Sprites at today's footprints, in today's draw order: stock desk / drafting table (desk top edge on the sprite's top
row), stock chair / mesh chair (behind the seated mangaka), arm lamp, reference shelf, coffee machine, assistants'

## Release 0.11.0 — characters (branch `upgrade/0.11.0-cast`)
1. `--sprite` mode in `scripts/pixelate.ts` with pure helpers in `pixelOps.ts` (cutout, bottom-align, downsample,
   PAL-key snap with a per-sheet key subset, outline to `L`, `closeOutline`, emit TS), unit-tested.
2. Generate pose sheets: mangaka (idle, walk x4, sit, drawing, stretch, sip, panic, asleep), editor (idle, walk x2),
   cat (sit, groom, stretch, sleep, walk). Hoodie prompted grey so it snaps to `J`.
3. Convert, validate (`frameRules`, `faceRules`, run cap ≤1.25x the frame replaced), graft the anchor head where
   needed, hand-touch walk cycles and collar/tie cells, keep FACES/marks aligned.
4. Re-measure 673/1079 and the `*_ART` baselines; update `SpriteAvatar` if the anchor head changed.
