# The Rising Mangaka 0.1.0: Decisions, Career Arc, Sound, Desktop — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: execute with the subagent-driven-development skill, one implementer per task, a task review after each, a whole-branch review at the end. Steps use checkbox (`- [ ]`) syntax. Every task is test-first (test-driven-development skill): write the failing test, watch it fail, implement, watch it pass.

**Goal:** Make player decisions matter, give the career a year-long arc, add sound and polish, ship the game as a Windows desktop app with CI, then push everything to the private GitHub repo.

**Architecture:** Gameplay stays in the pure, seeded simulation (`src/sim`). New game-driven moments are desk cards, never popups. Sound is a framework-free Web Audio module fed by a store bridge. **Tech stack:** React 19, TypeScript 6, Vite 8, Zustand 5, Vitest 5, happy-dom 20 + Testing Library 16, Web Audio, Tauri 2 (Rust 1.96, WebView2), GitHub Actions.

**Spec:** this document (Context, Decisions, Global Constraints) plus `DESIGN.md` and `CLAUDE.md` in the repo. The plan is committed to `docs/plans/2026-09-25-upgrade-0.1.0.md` before Task 1.

## Context

A balance readout across seeds 1, 42 and 99 showed the core loop is weak:

| Measure | Now |
|---|---|
| Serial offers earned | 1 of 18 one-shots |
| Typical score | 44 to 53 regardless of choices |
| Forced serials that survived | 0 of 3 |
| Money trend | rises even after last-place finishes |
| Pitch-screen offer odds | showed 0% on the manuscript that then earned an offer |

Root causes found in exploration: one global score weighting (Focus is worth under 1 point); pay ignores score; rival spread 12 swamps skill; the pitch estimate assumes every untested pairing is "Good" and ignores pacing noise; serials have no grace period; nothing happens over a year.

## Decisions (owner, 2026-09-25)

- Repo stays **private** on GitHub Free. No web hosting.
- Ship as a **desktop app** with **Tauri 2** (the machine has Rust 1.96, VS Build Tools C++, WebView2 153, Tauri CLI).
- Sound: **synthesized effects plus a light music loop** via Web Audio, no audio files.
- **All five packages** in scope; push to GitHub when done.

Rulings made while reconciling the three designs (the owner can overrule any):
- Studio visuals in the scene are keyed by the gameplay design's studio tiers and equipment, via `studioLook()`.
- The clock pauses and audio suspends when the window is hidden or minimised (browser and desktop).
- Zoom hotkeys stay **enabled** in the desktop app (accessibility); the layout is already responsive down to 375 px.
- The app icon is new art (rising sun and pen nib); the stock Vite favicon is replaced with the same art.
- Grace applies to every new series (first 4 chapters), not only the first.
- Work happens on branch `upgrade/0.1.0` in the main checkout. No worktrees (a previous run's `node_modules` junctions in worktrees deleted the main install).
