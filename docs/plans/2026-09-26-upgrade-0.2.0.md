# The Rising Mangaka 0.2.0: The Living Studio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: execute with the subagent-driven-development skill, one implementer per task, a task review after each, a whole-branch review at the end of each phase. Steps use checkbox (`- [ ]`) syntax. Every task is test-first (test-driven-development skill): write the failing test, watch it fail, implement, watch it pass. Before any "done" claim, run the gate (verification-before-completion skill).

**Goal:** Turn the game screen into a Kairosoft-style living studio: the pixel-art scene fills the window, every control floats over it, the characters do what the game state says, gains pop out of the scene, and every panel wears a matching pixel-frame look, without touching the simulation.

**Architecture:** The sim (`src/sim`) is untouched: a tick stays one day, the balance bands stay identical. Everything new is presentation: a second, non-persisted Zustand store (`src/state/clock.ts`) for the visual clock and unread-log marker; a bigger canvas (320×180) whose existing art is drawn through a constant offset; an actor table stepped per frame in `src/ui/scene/actors.ts`; DOM overlays (HUD badges, status card, rail, bubbles, pops) anchored over the canvas; and a pixel-frame UI kit (tokens + `base.css`) that every modal inherits. Sound gains five cues and a duck stack.

**Tech stack:** React 19, TypeScript 6, Vite 8, Zustand 5, Vitest 5, happy-dom 20 + Testing Library 16, Web Audio, `@fontsource/silkscreen`, Tauri 2 (unchanged).

**Spec:** this document (Context, Decisions, Global Constraints) plus `DESIGN.md` and `CLAUDE.md`. The plan is committed to `docs/plans/2026-09-26-upgrade-0.2.0.md` before Task 1.

## Context

The owner asked for the UI to be improved and laid out like Kairosoft's *The Manga Works* (reference screenshot: the studio room fills the screen; date, clock and money sit in the top corners; energy and points are stacked badges; a deadline chip; a column of icon buttons on the left; the current series as a compact status card at the bottom centre; Save and Menu in the bottom corners), and for the panels to be restyled to match, accepting a heavier game if it becomes more enjoyable and "feels more alive".

What the app has today (0.1.0): a three-row shell (HUD bar, a two-column main area with the 192×108 scene on the left and a 330-line desk panel on the right, an event log underneath); 12-fps sprite animation from a frame counter; a sky cycle in the window pane that runs once per game day; modern rounded panels with Nunito body and Bangers display type; the mangaka appears at the desk, in bed or standing, and nothing walks.

## Decisions (made by Claude at the owner's request, 2026-09-26; the owner can overrule any)

1. **Type.** `@fontsource/silkscreen` (400, 700) replaces Bangers as `--font-display` and becomes `--font-num`. Silkscreen is used only for titles, numerals, HUD badges and tab labels, at multiples of 8 px. Nunito stays for body copy and every button label (readability, the "show the why" paragraphs, and the contrast gate). Fonts stay fontsource packages: the desktop CSP is `font-src 'self'`.
2. **Layout.** Full-bleed, cover-fit scene; corner overlays; left rail; bottom-centre status card with a desk tray beside it for the desk cards; the studio log behind a rail button as a modal with an unread badge. Panels open as centred pixel-frame windows over a lightly dimmed scene (no blur) that keeps its idle animation.
3. **Canvas 320×180**, existing art offset by (+64, +36) through the shared pixel helpers (no `ctx.translate`: the fake canvas logs only `fillRect`). The new margins hold a kitchenette (left), the entrance wall with a front door on every tier (right) and front floor for walking (bottom). 24 fps.
4. **Lighting follows a game week, not a game day.** A game day is 1000 ms at speed 1 and 220 ms at speed 3; a full-screen per-day light cycle would strobe. The visual day is `t = ((day % 7) + fraction) / 7`, advanced in real time by the App's clock loop, and lives in the presentation clock store. The HUD shows the date, the weekday and a sun or moon mark. **No numeric hour clock** (it would claim a precision the game does not have).
5. **Actors.** A fixed-size actor table (mangaka, three assistants, the editor, the cat) planned from the snapshot and stepped in place per frame; characters walk (L-shaped paths, 40 px/s), sit, sleep and leave. Reduced motion snaps every actor to its target and freezes the frame.
6. **The editor visits.** When a manuscript is ready, a poll result or serial offer lands, an event or anime offer waits, or a year review is unread, the editor walks in the front door with the matching prop and stands by the desk until the moment is resolved. The results and offer modals mount only after `EDITOR_WALK_MS` (1400 ms, derived from the door-to-desk distance at 40 px/s; 0 under reduced motion) so the arrival is seen. Pillar 3 holds: nothing new blocks, and every desk card stays a card.
7. **Pops and bubbles are DOM**, anchored to scene coordinates through the cover-fit maths, so text is crisp, uses tokens and never lives on the canvas. Pops for money, fans and XP; bubbles for the latest info log line and the editor's greeting.
8. **Sound.** Five cues (`knock`, `pop`, `tab`, `open`, `close`); every modal ducks the music to 0.6 through a duck stack; the results modal keeps its 0.3 duck. The music loop is unchanged (a time-of-day variant is pointless when a light cycle lasts seven seconds).
9. **Scope kept out:** the sim, the balance bands, save shape (`SAVE_VERSION` stays 2), the Tauri shell, `npm version` (the owner runs it), save slots, achievements.
10. **Branch** `upgrade/0.2.0` in the main checkout (no worktrees: a previous run's `node_modules` junctions in worktrees deleted the main install). Four phases; the branch is pushed at the end of each so CI runs.

## Global Constraints

- Every task ends green: `npx tsc -b`, `npm test`, `npm run build`, `npx oxlint --deny-warnings`, `npm run contrast`. Phase ends also run `npm run check` and `npm run balance -- 1 20` (its rows must be byte-identical to `main`'s: the sim is untouched).
- **Sim purity:** nothing under `src/sim` changes. No new file imports from `src/sim` anything but pure helpers already exported from `src/sim/index.ts`.
- **Presentation state is never persisted:** `src/state/clock.ts` is a separate store; nothing is added to `store.ts`'s `partialize` list. `SAVE_VERSION` stays 2.
- **No per-frame allocation in the scene:** `render(ctx, snap, t, frame)` stays a pure function of its arguments; the actor table and the snapshot are mutated in place; sprites, palettes and seed tables are module constants; the fake canvas (`src/test/fakeCanvas.ts`) supports only `fillStyle`, `fillRect` and `imageSmoothingEnabled`, so every offset is arithmetic.
- **Coordinates:** old art coordinates + (64, 36). Everything must stay inside the phone crop box x 24–295, y 0–179, off the seated hero (old 74–85 × 48–62 → 138–149 × 84–98), the standing spot (old 112–123 × 62–76 → 176–187 × 98–112) and the editor's spot (204–215 × 102–116).
- **Blocking decisions unchanged:** the seven `pendingResult || pendingOffer` sites keep their meaning; the only change is that `ResultsModal`/`OfferModal` mount after the editor's walk. Auto-pause rules in `store.ts` `tick()` are unchanged.
- **Tests:** UI tests start with `// @vitest-environment happy-dom` and import `src/test/dom.ts`; fixtures come from `src/test/fixtures.ts`; expected values are hand-derived literals, never mirrored from the implementation. Every accessible name, button label, copy string and CSS class that an existing test queries (inventory in Appendix A) survives, or the test moves with the component and asserts the same thing.
- **UI rules (CLAUDE.md):** inline SVG icons only, no emoji; sentence case; no middle dots; buttons say what they do; tokens not raw hex in components (sprite palettes in scene `.ts` files exempt); both themes; 44 px touch targets on coarse pointers; `prefers-reduced-motion` respected (frame frozen, actors snapped, pops and rolls instant, CSS animations off); every hidden modifier has a UI hint.
- **Phone rule (CLAUDE.md, restated for the new layout):** at ≤ 640 px the scene is a 38vh band at the top with the corner badges over it; below it, in flow: the status card, the desk tray, the rail as a horizontal bar. At 375×667 in the drawing phase with the getting-started note dismissed, the Today control is visible without scrolling. A happy-dom test asserts the DOM order (Today seg before the desk tray before the rail); the manual QA step checks the pixels.
- **Contrast gate:** every new text/background pair is added to `PAIRS` in `scripts/contrast.ts`; token values stay flat hex (the parser stops at the first `}` inside a block).
- **Desktop:** nothing in `src-tauri/` changes; the CSP stays; F11 full screen keeps working with the full-bleed stage.

### Task 2: The presentation clock store and the App loop

**Files:** create `src/state/clock.ts`, `src/state/__tests__/clock.test.ts`, `src/ui/hooks/useClockLoop.ts`, `src/ui/__tests__/useClockLoop.test.tsx`; modify `src/ui/App.tsx`.

```ts
// src/state/clock.ts  (zustand create, no persist; store.ts never imports it)
export interface ClockState { day: number; fraction: number; t: number; logSeenId: number }
export const DAYS_PER_WEEK = 7
export const NIGHT_AFTER = 0.72; export const NIGHT_UNTIL = 0.06   // matches render.ts
const FRACTION_MAX = 0.999                                           // the next day is the sim's to announce
export const useClock = create<ClockState>()(() => ({ day: 0, fraction: 0, t: 0, logSeenId: 0 }))
export function weekT(day: number, fraction: number): number         // ((day % 7) + fraction) / 7
export function isNight(t: number): boolean                          // t > NIGHT_AFTER || t < NIGHT_UNTIL
export function advanceClock(dtMs: number, speed: RunSpeed): void    // fraction += dtMs / SPEED_MS[speed], capped; dt <= 0 ignored
export function syncClockToDay(day: number): void                    // fraction 0; same day is a no-op (same state object)
export function markLogSeen(nextLogId: number): void
export function unreadLogCount(log: readonly { id: number }[], seenId: number): number  // ids >= seenId
```
```ts
// src/ui/hooks/useClockLoop.ts
export const clockLoop: { now: () => number; raf: (cb: FrameRequestCallback) => number; caf: (id: number) => void }  // tests replace, like panels/useReveal.ts revealClock
export function useClockLoop(running: boolean, speed: Speed): void   // rAF while running: advanceClock(now - last, speed); cancels on stop/unmount
export function useClockSync(): void                                 // layout effect: syncClockToDay(game.day); markLogSeen(game.nextLogId) when worldSeed or saveLoads change
```
`useGameClock` keeps its `setInterval(tick, SPEED_MS[speed])` and adds `useClockLoop(running, speed)`; `App` calls `useClockSync()` beside `useTheme()`. HUD subscribers select booleans (`isNight(t)`), so 60 sets a second re-render nothing until night flips; the scene reads `useClock.getState().t` in its own loop.

- **Tests first** (`clock.test.ts`, node; reset state in `beforeEach`): `weekT(3, 0.5)` = 0.5, `weekT(7, 0)` = 0, `weekT(6, 0.999)` ≈ 0.99986 (5 places); `isNight`: 0.8 / 0.05 / 0 true, 0.5 / 0.72 / 0.06 false; `syncClockToDay(3)` then `advanceClock(500, 1)` → fraction 0.5, t 0.5; then `advanceClock(110, 3)` → fraction capped 0.999, t ≈ 3.999/7; `advanceClock(0, 1)` and `(-5, 1)` leave the same state object; `syncClockToDay(4)` → fraction 0, t ≈ 4/7, repeat returns the same object; `syncClockToDay(7)` → t 0; `markLogSeen(12)` → 12; `unreadLogCount([{id:1},{id:2},{id:3}], 2)` = 2, seen 4 → 0, empty → 0.
